# 2026-05-09 优化归档

## 今日目标

围绕“程序员一句感悟生成情绪 MV”的产品结果，重点优化成片质感、失败可排查性、生成链路可控性，并明确后续产品化方向。

## 产品判断

当前产品已经具备基础能力：

```text
用户一句真实感悟
→ 情绪/语义/表达分析
→ 字幕节奏
→ 意境与镜头叙事
→ 图片生成
→ 旁白/BGM/环境音
→ 最终 MP4
→ 报告
```

今天确认的产品重点：

- 结果质量优先，不只是流程跑通。
- 镜头之间要有叙事关系，不能只是关键词配图。
- 括号内容可能是反转、点醒、补充或价值判断，需要和主句分层理解。
- 停顿应该服务情绪呼吸，不应该制造频繁切图。
- LLM 开启时，关键分镜必须来自大模型；不能静默混入本地兜底，否则无法判断产品真实效果。

### 4. 停顿镜头节奏

问题：

之前每个 `...` 都会生成独立图片，导致一条 7 句内容变成 14 个视觉片段，中间很多 0.75s - 1.05s 的短停顿造成频繁切图。

当前策略：

```text
正文镜头：生成新图
中间停顿：复用上一张图
字幕：停顿时不显示
音频：保留停顿呼吸
视频：弱化前后淡入淡出
```

实现方式：

- `audio_plan_service.py` 为 `...` 镜头标记 `visual_hold_previous=true`。
- `image_service.py` 遇到该标记时复制上一张 `scene_*.png`。
- `video_service.py` 对复用镜头弱化转场。
- `image_generation_metadata.json` 记录 `visual_hold_reused_indices`。

当前验证结论：

- 实测观感明显更稳。
- 停顿呼吸感保留。
- 画面不再因为每个停顿都换图而跳动。

后续可继续优化：

- 停顿镜头可以不复制文件，改为视频合成阶段复用同一个路径。
- 普通停顿复用上一图，括号转折和结尾余味可考虑允许独立成图。
- `visual_hold_previous` 镜头运镜可进一步降低到极弱呼吸感。

### 5. BGM 生成稳定性

问题：

MiniMax `music-2.6` 曾出现：

```text
ProxyError
RemoteDisconnected
```

结论：

- 不是 token plan。
- 不是 API key。
- 不是模型配置成 free。
- 是网络/代理连接被远端断开。

当前优化：

- 音乐生成增加可配置重试。
- 默认同一模型最多请求 3 次。
- 默认重试间隔 `[5, 15]` 秒。
- 不再默认 fallback 到 `music-2.6-free`，避免 Token Plan 用户触发 `2061 your current token plan not support model`。

相关配置：

```json
{
  "music": {
    "model": "music-2.6",
    "request_timeout_seconds": 600,
    "retry_attempts": 3,
    "retry_backoff_seconds": [5, 15],
    "fallback_models": [],
    "fallback_on_error": true
  }
}
```

### 6. LLM JSON 协议稳定性

问题：

分镜阶段 MiniMax 返回了 `<think>...</think>` 和被截断/损坏的 JSON，导致 `storyboard` 失败。

重要产品原则：

```text
LLM 开启时，分镜必须来自大模型。
如果大模型没有返回合法 JSON，本次生成应该明确失败。
不能静默走本地兜底，否则会污染质量判断。
```

当前优化：

- `max_completion_tokens` 默认提升到 `8192`。
- 增加 `json_retries`。
- 第一次坏 JSON 后，会再次请求大模型严格输出完整 JSON。
- 如果重试后仍失败，流程明确失败并写入报告。
- 报错只保留响应预览，避免报告被超长输出刷爆。

相关配置：

```json
{
  "max_completion_tokens": 8192,
  "json_retries": 2,
  "json_response_format": false
}
```

参数说明：

- `json_retries`: 最多尝试几次拿到合法 JSON，总次数，不是额外重试次数。
- `json_response_format`: 是否向 OpenAI-compatible 接口发送 `response_format={"type":"json_object"}`；供应商不支持时保持 `false`。

### 7. 输入结构与括号意境分析

新增上游输入结构层：

```text
raw input
→ input_structure
→ emotion / expression_plan / visual_poetic_plan / narrative_plan / storyboard / image_prompt
```

输出文件：

```text
generated/runs/<run_id>/input_structure.json
```

核心字段：

```text
main_text
parenthetical_text
relationship
relationship_reason
emotional_shift
visual_transition
usage
question_analysis
```

关系枚举：

```text
none / explain / deepen / contrast / reveal / challenge / resolve / echo
```

落地方式：

- `emotion_service` 会读取主句/括号关系，避免括号完全覆盖主句。
- `expression_service` 会把括号关系写入 secondary unit。
- `visual_poetic_service` 会把输入结构纳入意境匹配文本。
- `narrative_service` 会让 secondary 镜头按括号关系转向，不再只重复主句压力画面。
- `storyboard_service` 会把 `parenthetical_relationship / question_strategy` 交给分镜。
- `image_service` 会把括号关系注入图片 prompt。
- `report_service` 会展示主句主题、括号主题和括号关系。

反问影响：

- 当前先记录 `question_analysis`，包括是否有问句、问句位于主句还是括号、反问可能性和后续策略提示。
- 后续做“提问环节”时，应优先复用 `question_analysis`，避免把反问错误当成普通括号解释。

V2 架构方向：

- 关系从单一 `relationship` 升级为 `primary_relationship + secondary_relationships + confidence`，避免复杂括号被一个标签绑死。
- 增加 `parenthetical_usage_mode`，区分括号是进入字幕、只影响理解、作为结尾回声，还是推动后半段转向。
- 增加括号位置与权重：`position / weight / should_shift_narrative`。
- 增加 `parenthetical_units`，把括号内部继续拆成 burden / direction / reveal / echo 等功能单元。
- 将括号和反问统一为 `secondary_layers`，避免后续分别维护“括号模块”和“反问模块”。
- 增加质量检查：括号是否被当成普通主句、视觉转折是否清晰、字幕使用是否匹配关系。

建议的 V2 目标结构：

```json
{
  "main_text": "...",
  "main_theme": "...",
  "secondary_layers": [
    {
      "type": "parenthetical",
      "text": "...",
      "position": "ending",
      "primary_relationship": "deepen",
      "secondary_relationships": ["resolve"],
      "confidence": 0.8,
      "theme": "...",
      "units": [
        {
          "text": "...",
          "function": "burden"
        },
        {
          "text": "...",
          "function": "direction"
        }
      ],
      "usage": {
        "subtitle": "include_as_secondary",
        "voice": "same_voice_inner_note",
        "narrative": "late_shots_redirect",
        "visual": "show_direction_not_repeat_pressure"
      }
    }
  ],
  "emotional_shift": {
    "from": "...",
    "to": "..."
  },
  "visual_transition": {
    "from": "...",
    "to": "..."
  },
  "question_analysis": {
    "has_question": false
  }
}
```

## 仍需关注

### 1. BGM 仍可能受网络影响

代码已经增加重试，但如果代理持续断开，仍会失败并使用本地 ambient fallback。

后续方向：

- UI 增加“只重试 BGM”按钮。
- 报告中突出 `music_generation_error.txt`。
- 支持用户手动上传 BGM。

### 2. 人物一致性还未根治

当前仍主要依赖文字连续性：

```text
same ordinary adult throughout
same visual world
same lighting logic
```

后续方向：

- 上传 1 张主角参考图。
- 上传三视图/背影/半身图。
- 建立角色资产包。
- 使用 image-to-image/reference image。

### 3. 音色一致性仍需继续优化

当前已经明确 `secondary_voice_id` 的意义，但更稳定的方案是：

- 主句和括号默认同一 `voice_id`。
- 只用 `speed / pitch / volume / emotion` 做轻微层次。
- 进一步实验整段一次 TTS + pause 标签。

### 4. 括号意境分层还可继续加强

今天明确了主句和括号不应混成一个主题。

后续应新增结构：

```text
main_theme
parenthetical_theme
relationship
visual_transition
```

### 5. 最终视频合成性能仍是瓶颈

当前慢点主要在 MoviePy `write_videofile`。

后续方向：

- 用 FFmpeg filtergraph 重写最终合成。
- 配置化 `crf / preset / fps / threads`。
- 支持只重跑最终合成。

## 当前建议优先级

下一阶段建议：

1. 音色一致性。
2. 括号意境分层。
3. BGM 重试/单步恢复 UI。
4. FFmpeg 合成优化。
5. 人物一致性参考图能力。
